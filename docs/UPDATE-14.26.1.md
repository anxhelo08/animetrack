# AnimeTrack 14.26.1 — iPhone local recovery storage

The recovery warning appears when the synchronous local library write fails. IndexedDB previously retained a verified copy, but every save still required an uncompressed full snapshot in localStorage. Historical migration backups occupied the same limited localStorage quota. This could block iPhone progress even when IndexedDB had room.

The repository now upgrades its existing IndexedDB database from version 1 to 2, preserving the libraries and recovery stores and adding an append-only backups store. Only explicitly recognized library migration backups are archived. Each is read back, validated and checked with SHA-256 before removing an identical localStorage duplicate; distinct copies, pending journals, credentials and other settings are preserved. The original library is backed up before changing storage encoding, and old sync payloads have their original backup prepared before migration.

Large existing write-ahead snapshots are compressed only after their complete IndexedDB record and original backup are verified. A quota-exceeded write can retry with lossless UTF-16 compression. The storage facade transparently reads both legacy JSON and the versioned encoded format. The logical library shape is unchanged; episode images, descriptions, personal notes, watch/unwatch timestamps, history and pending revisions remain intact. `lz-string@1.5.0` is pinned for the codec. This does not change the cloud payload, CSP, network hosts or public window globals.

The warning is retained for a genuine failure, such as unavailable/blocked storage or insufficient space even after compression. Its previous claim that only a small recovery copy was stored was inaccurate and has been corrected.

Validation: all five required commands (typecheck, lint, format:check, npm test, build) pass, including 561 unit tests. The performance bundle check passes within a 339000-byte gzip budget, increased by 3000 bytes for the codec and verified archival path. Browser regressions: 31 scenarios passed across desktop/phone Chromium, with 5 skips for the other layout. The two-device tests were rerun after replacing their old localStorage-location assertion with an exact archived-original check. These include anime/TV artwork, offline progress, PWA updates, navigation, 500-card identity retention and the unchanged CSP. The 500-title phone fixture rendered its first 30 cards in 991 ms at 4× CPU; this is a local fixture observation.

Behavior tests cover v1 database upgrade, exact original backups, append-only preservation, corrupt archive refusal, unavailable IndexedDB, Unicode roundtrip and a restricted 24000-character localStorage quota. The phone browser flow seeds a rich full library and duplicate backup exceeding that quota, loads without the blocking warning, saves an offline +1, reloads, and verifies progress, artwork, personal notes and untouched auth sentinel data.

Assumption and limits: the screenshot establishes a local save failure, not the precise iOS storage error; the fix addresses the full-snapshot/duplicate-backup quota path reproduced in tests. Browser tests use Chromium with an iPhone layout and injected storage limits, not a physical iPhone or Safari/WebKit. Older already-open tabs need reopening to load the storage decoder. No data-clearing step is required.
