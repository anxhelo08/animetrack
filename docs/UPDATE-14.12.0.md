# AnimeTrack 14.12.0

Search fields are search inputs with disabled browser/contact autofill and password-manager ignore hints. The global search guard covers dynamically mounted PC/phone/library/manga/calendar/command inputs, discards unexpected replacement by the current account's email, and preserves deliberate typing/paste and existing search form submission. Authentication inputs retain their original email/password autocomplete. Third-party managers can ignore website hints; their own popup UI is controlled by the extension/browser.

Calendar defaults to **watching + completed** with separate filters, week/month/agenda navigation, title search, upcoming/unwatched filters, source links, coverage details and reduced-motion support. Dates use the browser's local time zone. Unconfirmed sequels never inherit an old season ID or watched flags; the user updates parts before marking a new season.

The shared schedule loader uses exact AniList/MAL/TVMaze IDs. AniList supplies recent/upcoming schedule nodes and explicit SEQUEL relations. MAL/Jikan independently supplies confirmed episode dates, including the final episode page for long series and explicit sequels. Jikan requests are paced. TVMaze supplies known show episode airstamps and season numbers. Generic search-result/title matches and broadcast weekday estimates never create an episode. Only confirmed dates within the past 30/next 120 days are kept, bounded to 2,000 personal schedule entries. Provider failures retain saved information; AniList wins a conflict over the same MAL episode identity.

The existing five-minute authenticated dispatcher now also drains two daily schedule jobs per invocation. Public provider metadata is shared by exact lookup key, with a 24-hour successful-cache interval, one-hour failed-attempt retry, five-minute recovery lease and token-guarded finish. Watching/completed titles and all known parts are queued, including their provider aliases. Removed identities stop being refreshed after a day. Client reads fresh server cache on refresh/account load, then checks missing/stale metadata directly; manual refresh bypasses the cache. Existing visible-tab and daily catalog updates remain active, including the first update when there is no previous timestamp. Neither background worker writes personal status, progress, ratings or notes.

The public metadata table grants authenticated active sessions access to lookup key, result and checked-at columns only. Lease/identity internals, writes and queue functions are restricted to service role. SQL regression validates deduplicated completed-title identities, leases, daily freshness, protected grants and no personal-library overwrite; it is included in the disposable PostgreSQL test suite and was exercised with embedded PostgreSQL here.

Browser fixtures verify a synthetic Black Clover sequel to reproduce the missing-completed-title behavior; they do **not** claim a real Black Clover broadcast date. PC/phone checks cover search autofill, calendar filtering, coverage, responsive widths, WCAG checks and reduced motion. Live upstream availability can still delay new information; coverage makes that visible. AniList and direct Supabase HTTP requests are restricted by this workspace's network policy, so provider payload behavior is verified with deterministic responses and server deployment/permissions through the connected tools.

CLI migration creation failed because its startup attempted to write to the read-only home directory. The migration was saved directly, tested, and applied with the connected Supabase migration tool.

## 14.12.1 live verification

Live probes from the server exposed an invalid selection closing brace and AniList's rejection of `sort` on `Media.airingSchedule` (including the old daily query). The loader now uses `Page.airingSchedules` with explicit recent/future bounds and pagination; identity and schedule queries returned HTTP 200 from the real AniList endpoint. The old daily query no longer contains unsupported airing-schedule arguments. Confirmed local schedule events provide aired counts, and missing ongoing metadata does not reset them. Duplicate next-episode/schedule events are merged. MAL/Jikan full metadata also returned HTTP 200 from the server.

After deploying the corrected loader, the live dispatcher verification returned HTTP 200 with `airing.checked=2` and `airing.failed=0`; it sent no notifications during this verification.
